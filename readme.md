# Seismic Analysis Pipeline - Speed & Structure

## Overview
This repository implements a machine learning workflow for seismic velocity model inversion using synthetic shot-gather data. The goal is to accurately predict 2D subsurface velocity models from 5 receiver gathers per sample. The pipeline includes data inspection, feature engineering, clustering, geophysical analysis, and deep learning modeling combining both wide (hand-crafted) and deep (CNN) features for end-to-end inversion.

## Setup & Prerequisites

- Python 3.9+
- A local virtual environment is highly recommended.

1. **Install dependencies**:
   ```bash
   pip install -r requirements.txt
   ```

2. **Data Preparation**: 
   Ensure that the raw training and test data arrays are placed under the following directories:
   `data/raw/train_data/` and `data/raw/test_data/`.

## Workflow & Usage

### 1. Exploratory Data Analysis & Discovery
We use Jupyter notebooks for exploratory steps. Start checking data overview and basic features:
```bash
jupyter lab notebooks/01_data_overview.ipynb
```
Follow sequentially through `02_feature_engineering.ipynb`, `03_clustering.ipynb`, and `04_semblance_analysis.ipynb` to see semantic transformations, clustering analysis, and semblance visual approaches.

### 2. Feature Extraction
To build the tabular dataset for training, run the extraction pipeline which applies StandardScaler, computes PCA/UMAP embeddings, and filters out highly correlated features. This yields `final_features.csv`:
```bash
python src/extract_features.py
```

### 3. Model Training
Check `notebooks/06_modeling.ipynb` and `notebooks/experiments.ipynb` to train models. Current architectures rely on both "wide" tabular features and "deep" sequences extracted from the synthetic shot-gathers. Checkpoints and successful models are saved in the `models/` directory.

### 4. Inference & Contest Submission
After a model is available in `models/`, evaluate the test dataset and generate the `.npz` file compatible with the contest evaluator format:
```bash
python src/predictions.py
```
*Note: Make sure to verify `model_path` configuration inside `predictions.py` before generating.*

### 5. Evaluation
We use Mean Absolute Percentage Error (MAPE) to determine model accuracy. You can test submissions locally against a local ground truth:
```python
from utils import calculate_score
mape_score = calculate_score("answerkey.npz", "my_submission.npz")
print(f"Score: {mape_score}")
```
